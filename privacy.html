Data access and privacy

SEO Keyword Collector — Privacy Policy

What information is accessed through Google Ads API, how the desktop app uses it, and how the owner controls or deletes it.

Effective date: 13 October 2026 · Дата: 13 октября 2026 г.

1. Who operates the application

SEO Keyword Collector is a privately operated, local desktop SEO tool. It is not affiliated with or endorsed by Google. This public website explains a tool currently being configured. The application is intended for the owner and people they expressly authorize, rather than offering a public web service. For public questions, see the public project repository. For account-specific questions, contact the developer using the support email displayed on the Google OAuth consent screen. Never post OAuth tokens or personal information in public repositories.

2. What Google user data the app requests or accesses

When the owner explicitly authorizes the app via Google OAuth, the desktop tool requests permission to access their authorized Google Ads account data. Only the Google Ads API OAuth permission required by the tool is requested (https://www.googleapis.com/auth/adwords). The intended data includes:

  • the selected Google Ads customer/account identifier needed to route API calls;
  • historical keyword-planning statistics for user-provided keywords, including average monthly searches, monthly search volumes, competition and bid indicators where returned;
  • the geographic and language targeting settings the owner selects;
  • OAuth authorization tokens needed to authenticate API requests.

The tool does not request access to Gmail, Google Drive, Google Contacts, or Google Search Console. The app is designed for retrieving keyword-planning statistics; it is not intended to create advertisements, change campaign budgets, send emails or publish data to third parties.

3. Why and how data is used

The sole intended purpose is SEO keyword research and reporting for the sites/projects selected by the authorized owner. The application sends the owner's keyword list and targeting parameters to Google Ads API, receives aggregate keyword metrics, associates these with the project and chosen region/language, and produces local search-demand reports. OAuth credentials are used only to authenticate these requests. These practices are described here before any live OAuth access is configured.

4. Data sharing and third parties

The application's planned data flows are limited to communications with Google Ads API to obtain requested keyword statistics, and to local files exported by the owner. The operator does not sell, rent or share Google user data with third-party advertisers, data brokers or external analytics providers. Data is not used to train artificial intelligence models. No information is transferred to a remote backend operated by SEO Keyword Collector.

The public informational website is hosted by GitHub Pages. It does not contain account login forms, analytics tags, advertising trackers, or keyword submission forms. GitHub may process basic access information (for example IP address and request logs) under GitHub's privacy statement.

5. Storage, security and retention

The planned desktop application stores keyword lists and historical metrics in files and a local SQLite database on the owner's device. Authorization settings/tokens are stored locally and must not be checked into any public repository or shared with third parties. Data is transmitted to Google over HTTPS. The website itself does not store OAuth credentials, Google account data, or keyword lists.

Local keyword data and historical reports remain on the user's device until the owner deletes them. OAuth credentials may remain until removed or revoked by the user. There is no centrally managed cloud copy or externally imposed retention period for the desktop app's local reports.

6. Access, revocation and deletion

The authorized owner controls the local app data and can delete project files, reports, local database records and any stored OAuth credentials from their computer. Google account authorization can also be revoked at Google Account → Third-party connections. Revoking Google authorization prevents further access until new consent is granted; previously exported local files must be deleted separately by the owner.

7. Children's data and prohibited uses

The application is intended for professional SEO research, not children. It does not process personal images, create AI-generated content, or generate, edit or distribute intimate imagery. No Google user data is used for surveillance or for purposes unrelated to the described keyword reports.

8. Changes, accuracy and contact

This policy will be updated if the tool's actual data processing changes. Before requesting any additional Google user data, the owner should be informed and asked for any required new permissions. Application behavior must match these disclosures. For support, use the email shown in the app's Google OAuth consent screen. The website itself does not collect support submissions.

Google data use is subject to the Google API Services User Data Policy and OAuth 2.0 policies.

Какие данные получает приложение

После согласия владельца приложение получает доступ только к необходимым данным Google Ads API: выбранному рекламному аккаунту и агрегированной исторической статистике поисковых запросов (частотность, помесячная динамика, конкуренция). Для работы используется разрешение https://www.googleapis.com/auth/adwords. Данные Gmail, Google Диска и других сервисов не запрашиваются.

Для чего используются данные

Статистика нужна исключительно для SEO-анализа ключевых слов по сайтам, городам, странам и языкам. Приложение отправляет в Google Ads API фразы и параметры региона, получает значения частотности и формирует локальные отчёты. Оно не изменяет рекламные кампании и не размещает объявления.

Где хранятся данные и кому передаются

Ключевые слова, частотности, настройки авторизации и токены планируется хранить локально на компьютере пользователя. Срок хранения — пока пользователь не удалит файлы; результаты можно выгрузить в CSV. Данные передаются только Google Ads API по HTTPS для выполнения запросов, не продаются и не передаются рекламным посредникам. На информационном сайте нет форм входа, аналитических скриптов и сбора ключевых слов. Сам сайт размещён на GitHub Pages, который может вести технические журналы.

Как удалить данные и отозвать доступ

Пользователь может удалить базу SQLite, отчёты, настройки и OAuth-токены на своём компьютере, а также отозвать доступ в настройках Google-аккаунта. После отзыва разрешения новые запросы к Google Ads API потребуют повторной авторизации. По вопросам конфиденциальности используй адрес поддержки, указанный в окне согласия Google OAuth.
